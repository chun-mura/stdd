description: テスト設計書 (docs/test-design/) と実テストコードの乖離を検知し、ケースの実装状態を最新化する
argument-hint: [対象設計書パス。省略時は docs/test-design/ 全体]
---

対象: $ARGUMENTS (未指定なら `docs/test-design/` 配下の全 `.md`)

各設計書のテストケース一覧 (ID / 入力 / 期待結果) について、実テストコードとの照合を read-only サブエージェントに **単一メッセージで並列 dispatch** して調べる。各エージェントには設計書のパスとケース一覧のみ渡し、以下を調べさせる:

1. 各ケースをカバーするテスト関数が存在するか。テストコードのコメント・docstring に残された導出成果物やケース ID を優先手掛かりとし、なければ入力・期待値の一致で判定する
2. テストが存在する場合、アサーションが設計書の期待結果と一致するか (大きな乖離のみ報告。表現の細部は無視)
3. 逆方向: 設計書の対象モジュールに、ケース一覧にないテストが追加されていないか

調査が失敗した設計書 (対象テストが特定できない等) は「調査失敗」として明示し、レポート全体は止めない。

**判定基準**:
- テストが存在し期待結果と一致 → `実装済み`
- テストは存在するがアサーションが期待結果と不一致 → `乖離` (内容を具体的に記載)
- テストが存在しない → `未実装`
- ケース一覧にないテストが存在 → `設計外テスト` (ケース一覧への取り込み候補として列挙)

**出力**: 設計書ごとに「実装済み / 乖離 / 未実装 / 設計外テスト / 調査失敗」のレポートを提示する。判断は提示のみ — 書き換えは AskUserQuestion でユーザーに確認してから行う。承認された更新のみ、ケース一覧テーブルに「状態」列を追記・更新する (導出成果物や本文の他の部分には手を入れない)。
