description: テスト設計書 (docs/test-design/) と実テストコードの乖離を検知し、ケースの実装状態を最新化する
argument-hint: [対象設計書パス。省略時は docs/test-design/ 全体]
---

対象: $ARGUMENTS (未指定なら `docs/test-design/` 配下の全 `.md`)

各設計書について、まず `rg` でテストディレクトリ内の導出行 ID・ケース ID・対象モジュール名を検索し、候補テストだけを読む。候補が複数または ID がないケースは、該当ケースの D-ID をたどり、導出表から入力・期待結果を1行に投影して追加調査する。以下を判定する:

1. 対応テストと期待結果の一致
2. 設計書にない対象テストの有無

調査が失敗した設計書 (対象テストが特定できない等) は「調査失敗」として明示し、レポート全体は止めない。

**判定基準**:
- テストが存在し期待結果と一致 → `実装済み`
- テストは存在するがアサーションが期待結果と不一致 → `乖離` (内容を具体的に記載)
- テストが存在しない → `未実装`
- ケース一覧にないテストが存在 → `設計外テスト` (ケース一覧への取り込み候補として列挙)

**出力**: 設計書ごとに「実装済み / 乖離 / 未実装 / 設計外テスト / 調査失敗」を ID と1行理由で報告する。書換えはユーザー承認後、ケース表の `状態` 列だけを更新する。
